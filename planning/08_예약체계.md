# 08. 예약체계 + 관리자탭

> 작성일: 2026-07-14 · 상태: **v1 구현 (배포는 D1 연결 5분 설정 후 활성화)**

## 1. 확정 결정사항 (2026-07-14 사용자 확정)

| 항목 | 결정 |
|---|---|
| 확정 방식 | **신청 → 운영자 확인·승인 → 확정** (자동확정 없음) |
| 알림 | **반자동 원클릭 문자** — 관리자탭 버튼 → 문자앱이 내용 채워진 채 열림 (비용·세팅 0). 예약량 증가 시 문자 API(솔라피 등) → 알림톡 순 확장 |
| 메뉴 | 단일 메뉴 — **1:1 타로리딩 (대면) · 30분 · 5,000원** |
| 슬롯 | **30분 간격** (기본 그리드 10:00~21:30, 관리자가 열고 닫음) |
| 관리자 잠금 | **비밀번호 1개** — Cloudflare Secret(`ADMIN_PASSWORD`), HMAC 토큰 쿠키 30일 |
| 결제 | **현장 결제** (PG 없음) — 방문 시 현금/이체/카드 |

## 2. 아키텍처

```
myoyeon.capshinsmg.workers.dev (Worker 1개)
├── 정적 에셋 app/          ← 랜딩 + /admin/ 관리자탭 (에셋 매치 우선)
├── worker/index.js          ← 에셋에 없는 경로 = /api/* 처리
└── D1: myoyeon-db           ← slots · reservations · events
```

- **스키마 자동 생성**: 워커가 첫 요청에서 `CREATE TABLE IF NOT EXISTS` 실행 → 대시보드에서 SQL 돌릴 필요 없음 (worker/schema.sql은 참고용)
- **안전한 단계 배포**: `wrangler.jsonc`의 D1 바인딩은 DB 생성 전까지 주석 상태 → 바인딩 없어도 배포 성공, 랜딩 정상. 예약 API만 503 응답 → 프론트가 **인스타 DM 안내로 자동 폴백**
- 로컬 개발: `wrangler.dev.jsonc` (로컬 D1 + 개발용 비밀번호 포함) — `npx wrangler dev -c wrangler.dev.jsonc`

## 3. DB 스키마 (요지)

- `slots(id, date, time, UNIQUE(date,time))` — 행 존재 = 열린 슬롯
- `reservations(id, slot_id, name, phone, note, category, status, created_at, updated_at)` — status: `pending → approved | cancelled`
- **부분 유니크 인덱스**: `reservations(slot_id) WHERE status IN ('pending','approved')` → 동시 신청 경합에서도 더블부킹 원천 차단
- `events(name, date)` — 퍼널 로깅 (page_view → draw_start → result_view → booking_open → booking_submit, share_save)

## 5. 유저 플로우 (S5 예약 시트 · S6 완료)

결과 화면 [1:1 타로리딩 예약하기] → 바텀시트 3스텝 (js/booking.js):

1. **메뉴 확인** — 단일 메뉴 카드(30분·5,000원·현장결제) + 뽑은 카테고리 이어받는 문구 (예: 연애 → "오늘 뽑은 연애 카드 이야기를 더 깊이")
2. **일시 선택** — 14일 날짜 칩(열린 슬롯 있는 날만 활성) + 30분 시간 pill
3. **정보 입력** — 이름 · 연락처(자동 하이픈) · 궁금한 점(선택) + **개인정보 동의 체크**(수집 항목·목적·파기 고지)
4. **완료(S6)** — 접수 요약 + "운영자 확인 후 문자로 확정 안내" + 팔로우 유도 + 재방문 훅

- 픽셀 스텁: 시트 열림 `InitiateCheckout`, 신청 완료 `Schedule` (12단계에서 실 ID)
- API 실패/미연결 시 → 기존 **인스타 DM 시트로 폴백** (서비스 무중단)

## 6. 관리자탭 `/admin/` (A1~A4)

| 화면 | 내용 |
|---|---|
| A1 로그인 | 비밀번호 1개 → 30일 쿠키. 실패 시 0.4초 지연(무차별 대입 감속), `noindex` |
| A2 예약 | 필터(대기/예정/전체) · 카드형 목록(이름·전화(탭=발신)·일시·카테고리·문의) · **[승인][거절]** · **원클릭 문자 3종**(확정/리마인드/취소) — `sms:` 링크로 문자앱 프리필 |
| A3 시간표 | 날짜 칩 + 10:00~21:30 30분 그리드 토글 (닫힘/열림/예약됨-잠김) + [전체 열기/닫기] |
| A4 통계 | 대기·확정(예정)·누적 카드 + 퍼널 표(방문→뽑기→결과→예약열람→신청, 오늘/7일 전환율) |

### 문자 템플릿 (admin.js)

- 확정: `[타로공방 묘연] ○○님, 7/15(화) 14:00 타로리딩 예약이 확정되었어요 🌙 (30분·5,000원·현장결제) 공방 위치: {주소} …`
- 리마인드: 전날 [내일 예약] 목록에서 버튼 1탭
- 취소/거절: 사과 + 재신청 링크
- ⚠️ **공방 주소**: `app/admin/admin.js` 상단 `SHOP_ADDRESS` 상수 — 실제 주소로 교체 필요 (현재 플레이스홀더)

## 7. 배포 활성화 체크리스트 (사용자, 약 5분)

1. Cloudflare 대시보드 → **Storage & Databases → D1 → Create database** → 이름 `myoyeon-db`
2. 생성된 **database_id 복사 → 클로드에게 전달** (wrangler.jsonc 주석 해제 + id 기입 후 push는 클로드가)
3. **Workers & Pages → myoyeon → Settings → Variables and Secrets** → Add → Type **Secret**, 이름 `ADMIN_PASSWORD`, 값 = 관리자 비밀번호
4. (선택) `RESEND_API_KEY` + `ADMIN_EMAIL` 추가 시 신규 신청 이메일 알림
5. Settings → Build에서 Deploy command가 `npx wrangler deploy`인지 확인
6. 배포 후 `/admin/` 접속 → 로그인 → 시간표에서 슬롯 열기 → 랜딩에서 테스트 신청 1건

## 8. 확장 로드맵 (v2+)

- 문자 자동발송 API(솔라피/알리고, 건당 ~10원) → 카카오 알림톡(사업자+채널 후)

- 노쇼 표시·차단, 후기 요청 자동화(10~11단계 소재 파이프라인 연동)
