# 09. 인스타 ↔ 랜딩 동기화

> 작성일: 2026-07-15 · 상태: **v1 구현 (유입 추적 라이브, 바이오 링크 설정은 사용자 액션 §4)**

---

## 1. 목적

1. 프로필 → 랜딩, 랜딩 → 프로필의 **상호 링크 완성**
2. **유입 경로(UTM)가 퍼널 이벤트와 예약 데이터에 찍히게** — 12단계에서 "광고비가 예약이 됐는가"를 판단할 유일한 근거

## 2. 표준 링크 맵 (UTM 정책 — 이대로만 사용)

| 위치 | 링크 | 집계 표기 |
|---|---|---|
| 인스타 바이오 | `https://myoyeon.capshinsmg.workers.dev/?utm_source=instagram&utm_medium=bio` | `instagram/bio` |
| 자체 스토리·하이라이트 링크 스티커 | `…/?utm_source=instagram&utm_medium=story` | `instagram/story` |
| 메타 광고 (12단계) | `…/?utm_source=meta&utm_medium=paid&utm_campaign={캠페인}&utm_content={소재}` | `meta/paid` |
| 유저의 스토리 공유로 온 지인 | 링크 부착 불가 (이미지 공유) → 워터마크 보고 검색 유입 | `direct` |
| 파라미터 없는 직접 접속 | — | `direct` |

- 규칙: **utm_source = 어느 플랫폼**, **utm_medium = 어떤 지면**. 캠페인·소재 구분은 광고에서만 사용
- 저장 형식: `{source}/{medium}` 문자열 (예: `instagram/bio`) — 세션 동안 유지되어 이후 모든 이벤트에 따라붙음

## 3. 구현 (2026-07-15)

| 위치 | 내용 |
|---|---|
| `app/js/main.js` | 접속 시 UTM 캡처 → sessionStorage 유지, `window.getSource()` 제공. 픽셀 이벤트 파라미터에도 `traffic_source` 첨부 |
| `app/js/booking.js` | 퍼널 이벤트(`/api/event`)와 예약 신청(`/api/reservations`)에 `source` 포함 |
| `worker/index.js` | `events.source`·`reservations.source` 컬럼 (자동 마이그레이션), 저장 시 정규화(영문·숫자·`/`·`-`만, 40자), 통계 API에 유입별 방문·신청 집계 추가 |
| `app/admin/` | A2 예약 카드에 유입 배지(📍 instagram/bio), A4 통계에 **[유입 경로 (7일)]** 표 (방문·신청) |
| `app/index.html` | OG 태그 절대경로 + `og:url` — 카톡·DM 링크 미리보기 정상화 |

- 랜딩 → 인스타 링크는 기존 구현 유지: 결과 화면 `@myoyeon.tarot` 버튼 + 예약 완료 화면 팔로우 버튼
- 구버전 이벤트(컬럼 없던 시기)는 `direct`로 집계됨

## 4. 사용자 액션 (계정 설정은 직접 해주셔야 해요)

- [ ] 인스타 앱 → 프로필 편집 → **웹사이트** 란에 바이오 링크(§2 첫 줄) 붙여넣기
- [ ] 바이오 소개 문구는 04 §3 확정안 유지 ("…예약도 아래 링크에서")
- [ ] 스토리·하이라이트에서 링크 스티커를 쓸 때는 반드시 §2의 story 링크 사용
- [ ] 설정 후 본인 폰으로 바이오 링크 접속 1회 → 관리자탭 📈 통계 → [유입 경로]에 `instagram/bio` 방문이 찍히면 성공

## 5. 확인 방법 (운영 중)

- 관리자탭 → 📈 통계 → **유입 경로 (7일)**: 어느 지면에서 방문·신청이 오는지 한눈에
- 예약 카드의 📍 배지: 이 손님이 어디서 왔는지 개별 확인
- 12단계 광고 시작 후: `meta/paid` 행의 방문 대비 신청 비율 = 광고 → 예약 전환의 실측값
